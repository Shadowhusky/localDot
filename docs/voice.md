# Voice input

The composer uses a local speech model on the computer running localDot when there is one, then browser on-device recognition, then the browser's online recognizer only when enabled in Voice settings. A configured local model takes priority over online speech, on every device that reaches this computer, phones included. Audio is never sent to a model provider for local transcription.

The local route captures mono PCM in an AudioWorklet, resamples to 16 kHz and updates the draft approximately every four seconds plus model processing time. Only one preview request runs at once. Stop flushes the final samples and releases microphone tracks before waiting for transcription; Send waits for that final text; Cancel discards the recording and restores the draft. A new turn owns a new audio graph. Leaving or reloading the page releases capture. Audio lives in browser memory, and on the server in private files under `<home>/voice-audio/` while it's transcribed; those files are removed afterward, and the folder is emptied when the daemon starts, in case it stopped mid-way. Locked folders are given back their write permission first (links are removed as links, never followed); anything still impossible to remove is moved aside to `voice-audio.stale-*` so start-up carries on with a fresh folder, and every later start tries again to remove those folders and any `voice-audio-*` fallback, logging what still can't go. An installed model reads a long recording in pieces of at most 15 seconds, cut at pauses and at most three to a run, because these models fail or wander on longer audio and hold each run's pieces in memory together. The agent receives only submitted text.

AudioContext is resumed synchronously in the initiating click before requesting microphone permission. Where available, Audio Session is set to play-and-record while capturing and restored afterward. This avoids using a second microphone alongside Web Speech recognition. Snapshot waits are bounded; digital silence is not submitted to the model. The browser route still has bounded startup/retry timeouts where no local model is available.

WebKit has an unresolved report of browser SpeechRecognition becoming silent after audio/video playback: [WebKit 321436](https://bugs.webkit.org/show_bug.cgi?id=321436). Retrying that same browser service is not a reliable recovery. Local transcription avoids that service entirely and measures actual microphone samples for the waveform. Desktop WebKit tests do not substitute for testing iOS hardware or OS microphone permission behavior.

## Installing speech

Settings → Voice and the optional **Talk to dot** step of setup install a speech model with one press. [Speech models](speech-models.md) says which models, why, and how they were measured.

| Tier | Model | Download | Memory at most | Good at |
| --- | --- | --- | --- | --- |
| Light | SenseVoice Small, int8 | about 180 MB | 520 MB | The quickest, even on an older computer. Chinese, English, Cantonese, Japanese, Korean |
| Balanced | X-ASR zh-en, int8 | about 155 MB | 900 MB | The most accurate for Chinese, and for Chinese mixed with English, with punctuation. Good English too |
| Most languages | Qwen3-ASR 0.6B, int8 | about 860 MB | 2 GB | The strongest English, and about 30 languages. Slower, and it needs a capable computer |

Downloads include the 20–28 MB speech program, once. The daemon reads memory, cores and architecture on the computer running localDot and suggests a tier: Balanced, or Light where Balanced would crowd or crawl. It warns honestly about the rest and always lets the person choose. Only the program's `-offline` command and ONNX Runtime are kept; neither runs when nobody is talking.

Nothing downloads until someone presses. Only the owner can start, cancel or remove it: `GET`/`POST`/`DELETE /api/voice/install` and `POST /api/voice/install/cancel` are on no shared link's allowlist. The computer does the download whichever device asked, so it survives a page reload and shows on every device; the page polls while it runs. Setup never waits for it.

The stages are: check free space; download the speech program; download the speech model; check and unpack the files; try it once on a second of silence. A dropped connection resumes with a range request, a stalled one retries, and a daemon restart keeps the partial files and shows Retry rather than carrying on unasked. A file that arrives whole from one source and fails its hash moves straight on to the next source; one built on kept partial bytes gets one fresh try first. Cancel removes what was fetched, and a press while it clears away is refused until it has finished. Changing tier keeps the current one working until the new one has passed; a failed or cancelled change leaves it as it was.

Everything lands in `<home>/speech/`, private to the user, and Remove deletes only that folder. Every delete refuses a path that resolves outside it, and refuses anything at all while `<home>/speech` is itself a link; the folders the install writes to are replaced if they've become links. Every file is pinned by SHA-256 in `apps/daemon/src/voice/speech-catalog.ts`, which ships inside the daemon: a release's signed catalog covers it through the package inventory, and a source checkout through its commit. `installed.json` records only the tier and the program version, and is used only when both match the catalog exactly; the program, its files, flags and arguments always come from the catalog. A version this catalog doesn't know is shown as needing a reinstall and is never used in a path.

Nothing runs before its hash matches. Installed files are hashed again when the daemon starts, and the program once more right before its first run during an install. Before every run, every folder from `<home>/speech` down to the program and to the model must be a real folder, not a link, so the loader resolves its library folders from the same place they're checked; the program's and the model's folders must hold exactly their pinned files, as plain files, and nothing else; and none of the folders the program searches for libraries before the system's (its LC_RPATH on macOS, DT_RPATH on Linux, listed per build in the catalog) may exist outside its own folder. A file whose size, inode, modification time or change time (ctime, which any write moves) differs from when it was hashed isn't run until its hash has been checked again. Installing again replaces anything planted beside the files. Otherwise Settings offers to install again and speech falls back to whatever else is available. These checks are made before the program starts, so something able to write to the folder between the check and the start could still get in: they guard against leftovers and tampering at rest, not against another process of the same user racing them.

## Whisper you installed yourself

A [whisper.cpp](https://github.com/ggml-org/whisper.cpp) you set up by hand keeps working (`brew install whisper.cpp` on macOS, with a multilingual GGML model in `~/.cache/whisper.cpp/`, or named by `LOCALDOT_SPEECH_MODEL` in the daemon's environment). Homebrew's current `share/whisper.cpp` and older `share/whisper-cpp` directories are also recognized. Settings shows it as your own; localDot only reads it and never changes or removes it. A model named in `LOCALDOT_SPEECH_MODEL` comes first, then what localDot installed, then any Whisper found, so setting up localDot's model doesn't stop it working: remove localDot's and it's back in use. An English-only model is used only for English.

The authenticated `GET /api/voice` reports whether a model is available and the languages it hears, so a language it doesn't cover goes to the browser's speech instead. Transcription uses the existing authenticated WAV endpoint; both browser recording and server requests are bounded, with longer limits for longer recordings. Cancellation reaches the child process. Setup failures release the busy flag so future recordings can proceed.

## Verification

Unit tests cover capture ownership, cancellation during permission, page reload cleanup, resampling, silent audio, progressive text, final flush, stale responses, service discovery and server lock release, and for installing: checksum mismatch refusing to run, resume, cancel, a full disk, route choice, guests refused and a hand-installed Whisper left alone. `speech-install.spec.ts` walks the setup step and every stage in Settings in both colour schemes. `LOCALDOT_TEST_SPEECH_INSTALL=1 pnpm vitest run apps/daemon/src/voice/speech-install.real.test.ts` installs for real into a temporary home and turns audio into text. The opt-in `composer-voice-capture.spec.ts` exercises actual AudioWorklet capture and the local Whisper model in Chromium and mobile WebKit. Set `LOCALDOT_TEST_SPEECH_AUDIO` to a synthesized WAV containing “voice recording”, `LOCALDOT_TEST_SPEECH_MODEL` to the GGML file, and `LOCALDOT_TEST_SPEECH_BINARY` to whisper-cli, then run the spec with projects c14 and w39. It injects synthetic audio into a Web Audio input graph, requires local transcription responses and tests Stop, Cancel, Send, reload and subsequent recordings without accessing a person's microphone.
