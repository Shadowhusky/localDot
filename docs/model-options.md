# Model controls

Reasoning controls reviewed against vendor documentation on 2026-10-31 (the full capability matrix, with sources, is [providers.md](providers.md)); speeds on 2026-10-21. Implementation: `packages/providers/src/model-options.ts` and `speeds.ts`; HTTP contract tests: `cells/brain/src/model-options.test.ts` and `served-speed.test.ts`.

## User behavior

The model button inside the desktop and phone composer opens **Model & thinking**. Choose a model, adjust its supported effort, thinking budget, answer detail or speed, then Apply. Escape discards the draft. Reset restores provider defaults. The same controls appear in Settings for Main, Fast and Local roles. Changing models clears incompatible options. Existing tasks retain their immutable model/settings snapshot; new choices apply to a new task. The composer's model button shows the effort and, when Fast or Ultrafast is chosen, a bolt (two for Ultrafast).

The **Fast model** summarizes the older half of a long task and answers the purpose check when no Jev key is saved. It can be another model of the main model's provider: choosing that provider fills in the main model's key (and a custom endpoint's format, flat-rate plan and speed-tier switch) and suggests the cheapest other model the catalog lists, a model the endpoint ran before, or Claude Code's Haiku. Beside a Claude Code main model, the fast model is one of Claude Code's own: Claude Code keeps its own history, so it only answers the purpose check, as a one-turn question to the user's Claude Code with no tools, MCP servers or saved session, and its usage shows as the task's Fast row. The ChatGPT plan can't be a fast model: one Codex process at a time holds the account's credentials, and a working task holds it when the check would need a second. A fast model that can't work beside the current main model (an API model beside Claude Code, a Claude Code model beside an API model) is kept and shown as off until the main model changes back. First-run setup offers a fast model for catalog providers and, by model ID on the same address, key and format, for custom endpoints.

Unconfigured options are omitted from requests. “Provider default” does not guess a provider's current effort. Unknown model IDs and endpoints without a verified contract show a default-only explanation. A model catalog's `reasoning` flag alone is not evidence that a model accepts a particular parameter.

## Limits and validation

Options form a strict, bounded schema. Arbitrary request-body keys, sampling controls, URLs and credentials cannot enter requests through this setting. Unsupported values are rejected again by the daemon and brain, even if submitted outside the UI. Effort and budget are mutually exclusive; defaults remain omission. Saved budget choices must leave 1,024 tokens within the existing output cap for an answer, with a maximum budget of 15,000.

For shorter internal requests such as compaction, the selected budget is reduced to fit that request. Anthropic's SDK adds manual thinking tokens to `maxOutputTokens`, so the wrapper subtracts them first to preserve the total limit used by admission/accounting. Stateless Responses requests retain `store:false` and encrypted reasoning for tool turns. SDKs continue to handle reasoning signatures and replay.

Not included: service tiers outside the Standard, Fast and Ultrafast vocabulary (flex, scale, Vertex's shared and dedicated tiers), premium/pro models, arbitrary temperature/top-p, provider-hosted tools, safety settings or permission controls. These differ in billing or execution behavior and are not interchangeable with effort. The UI does not represent effort as a guarantee of answer quality or expose hidden reasoning text.

## Verification scope

Automated tests exercise actual installed SDK HTTP serialization for every implemented API mapping (including both China/global endpoints and coding-plan aliases), native effort forwarding, strict rejection, defaults, reset, saved settings and token caps. Browser checks cover Chromium desktop/phone and WebKit phone, keyboard use, reload persistence, Escape/focus restoration and CSP. Vendor contract tests intercept requests at the network boundary; they are not live paid calls to every vendor. Live checks are limited to configured credentials and are recorded separately.

## Startup discovery and offline behavior

Every daemon startup schedules a background catalog refresh; opening the app also requests a check, coalesced across tabs with a one-minute retry interval. The last verified catalog is served immediately. Provider metadata is fetched through keyd with stand-ins, bounded GET-only requests and no paid generation calls. Task bindings snapshot the advertised controls, so a background refresh cannot change a running task.

Anthropic's [Models API](https://platform.claude.com/docs/en/api/http/models) reports supported effort levels and thinking modes. These replace bundled choices, including capabilities newly advertised for an existing catalog model. OpenRouter's [model metadata](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) advertises parameter support; absent reasoning support removes those controls. Native ChatGPT and Claude Code use their account/runtime model metadata.

The [OpenAI model list](https://developers.openai.com/api/reference/resources/models/methods/list) and DeepSeek model list do not publish effort enums or speed support. Their successful model-list checks cannot establish new effort levels; documented bundled contracts remain the fallback. Custom gateways are not assumed to publish a vendor's capabilities. Unknown options remain hidden rather than inferred from a reasoning boolean. Cached capabilities survive partial provider outages; requests are bounded, cancellable on shutdown and use a separate short-lived listener with a zero generation budget.

## Speed (2026-10-21)

Speed is an opt-in choice of `standard | fast | ultrafast`, separate from effort; unset is the provider's default, which the UI calls Standard. Each model lists the speeds it offers, and each premium speed carries its price over the standard rate (`speedTiers` in `packages/providers/src/speeds.ts`). The Speed row offers only those, each with its price, or "Uses more of your plan" (ChatGPT) and "Uses usage credits" (Claude Code) for plans.

| OpenAI | GPT-6.x and GPT-5.x except nano, pro and chat/search: 2×; GPT-5.5: 2.5× | GPT-6.1 Sol and GPT-6 Astra: 6× | `service_tier: priority` / `ultrafast` (Responses API) |
| Anthropic | Opus 5.5, 5 and 4.8: 2× | — | `speed: "fast"`; the installed SDK adds `fast-mode-2026-02-01` |
| Google Gemini API | 3.8 Flash, 3.6 Flash, 3.5 Flash-Lite, 3.1 Pro, 3.1 Flash-Lite, 3 Flash, 2.5 Pro, Flash and Flash-Lite: 1.8× | — | `serviceTier: "priority"` (not Vertex) |
| xAI | Grok text models: 2× | — | `service_tier: priority` |
| OpenRouter | `openai/`, `anthropic/`, `google/` and `x-ai/` models as their vendors offer them | `openai/` GPT-6.1 Sol and GPT-6 Astra | `service_tier: fast` / `ultrafast`, capped by `provider.max_price` at the rate the task set aside, so a pricier endpoint is passed over |
| Custom endpoint, OpenAI formats, with **Supports speed tiers** on | OpenAI model IDs as OpenAI offers them; any other model at an unknown premium | Responses format only | As OpenAI; the brain adds `service_tier` where the OpenAI package drops it for model IDs it doesn't know |
| ChatGPT plan | Where the account lists the tier (2.5× plan usage) | Where the account lists it (8×, Pro and Enterprise) | The account's own tier id as `serviceTier` |
| Claude Code | `opus` and Opus 5.5/5/4.8, as the account's model list says | — | `settings.fastMode`, billed to usage credits |

Not offered: Groq's `performance` tier (Enterprise only, no published premium), Azure deployments, Vertex, DeepSeek, Together and the other compatible presets, and Gemini 4 Argon, which has no published priority price.

A task with a premium speed sets aside its premium times the catalog or manual rate, without cache discounts, in the immutable keyd pricing snapshot; an unknown premium sets aside the highest one any vendor charges (2.5× Fast, 6× Ultrafast). Providers may serve a premium request at the standard tier and bill that, so the reservation can exceed the bill. Two roles on one model at different speeds reserve the higher rate for both.

Each model call records the speed its provider says served it: OpenAI's and xAI's `service_tier`, Anthropic's `usage.speed` (also in Claude Code's stream), Gemini's `x-gemini-service-tier` header or usage metadata, and the `service_tier` of an OpenAI-style chat completion's chunks or body (OpenRouter, custom endpoints). The turn's line in the conversation, its details and the task's usage show a bolt for those calls; a call served at the standard tier shows none. The pinned Codex runtime reports no tier per turn, so ChatGPT plan turns carry no bolt.
