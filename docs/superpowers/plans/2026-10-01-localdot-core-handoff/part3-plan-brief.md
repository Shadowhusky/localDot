## Scope of Part 3
- `desktopd` (in the desktop cell, extending Part 2's skeleton): perception through Cua Driver (`cua-driver mcp --no-overlay`, pinned 0.30.4, perception only) — observe (screenshot + windows), hitTest (accessibility element at a point, with frames mapped to desktop device pixels per toolkit using the spec's exact formulas), CDP for Chromium web-content boxes; input through its own XTest client (window activation and focus handled itself) with an XI2 raw-event listener that timestamps every press (`input()` returns the XI2 raw-press time); type (keys through the same injector; `text.progress` from the same listener; secret-field masking at the source); settle (screen-quiet detection). Clock mapping desktopd ↔ daemon by periodic lowest-RTT ping.
- Calibration: a tool that measures raw-press → frame latency per injector and scale with ≥ 500 trials on the target machine and writes the p99 table the gateway uses (the development Mac's first numbers: own XTest clicks 19.6 ms at 1× / 23.1 ms at 2×, keys 19.1 / 29.3 ms) — the measurement uses desktopd's own client, not xdotool.
- Action gateway in the daemon: intent → target → dispatch → settle events in the log (Part 1's protocol), presentation timing (Fitts-style travel from `@localdot/stage`, dwell 90 ms ÷ speed, presentation speeds), dispatch on the completed call, hold dispatch while the stream connection is stalled, ring onset = XI2 raw press + that injector's per-scale p99. Success criterion 3 (A1) is pending the user's sign-off between this policy ("keep") and "strict" (start the ring on the first frame that changes at the dispatch point, with p99 as the timeout): isolate the onset policy behind one small interface so "strict" is a contained change, implement "keep", and say in the plan exactly what changes if the user picks "strict".
- The puppet: a scripted action driver (no LLM) that feeds the gateway — used for demos, the e2e test and the pixel oracle.
- P0 overlays rendered by `packages/stage` (`render(log, t, view)`) into Part 2's stage canvas: cursor (with hotspot), travel path, target outline (solid xenon with dark halo when acting; neutral dashed "looking at"), click ring, typing pill/caret, the HUD/caption states; xenon only while the agent has control; reduced-motion support.
- Pixel-oracle tests per the amended spec's Testing section (drawn cursor hotspot within 2 px of the dispatch point at 1×, 2× zoom and HiDPI; no click ring before the input's raw press or more than one frame before the frame that shows a press-acting control's change; typing display never ahead of typed characters; …).

- End-to-end acceptance: the puppet runs a scripted multi-app sequence (e.g. open Calc, click a cell, type, open Chromium, click a link) live in the UI with the overlays, screenshot/recording-verified, and the pixel oracle passes.
